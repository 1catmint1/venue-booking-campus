服务校园课余锻炼、社团周期训练和场馆日常协作。预约、持久候补、模拟付款与退款递补共用服务端事务，按学生/教工/校外身份与场次价表保存价格快照；工作台按角色和范围授权。原复现基线与私有历史库保留。

## 当前入口与版本

[正常共享体验入口](https://venue-booking-mobile-demo-20261014.woodsyguppy2048.chatgpt.site/)继续使用Web v1.4.0。本次v1.5.0在独立owner-private环境完成实现与验收，源码和构建单独交付。Windows正常联网启动器仍打开原正常入口，隔离候选启动器单列；原生ArkTS/rawfile组件按v1.3.0归档识别。本轮暂不向社区或赛事平台提交。

## 低延迟实现与验收

空闲请求直接执行；使用排队延迟反馈、有限自适应执行额度和短微批。事务提交结果携带本人快照，界面立即显示已确认结果，后台对账失败不会把提交成功改报失败。同一浏览器写操作依次确认，确认期间暂缓切换模拟身份。SQL容量约束、幂等、授权、原订单价款及候补持久序号继续有效。

按10/30/50/100账号重复突发，另测1000账号扩展波次。实际应用RPC分别记录预约、候补和模拟支付，计时包含首发前准入及重试；网络、服务端观测、API端到端与界面样本分别报告。完整对照每版15590条采样、420项一致性断言通过。公网预约/候补P99仍高于100ms，当前参数在部分档位增加了排队，因此本次交付隔离候选与诊断结果，正常入口维持现版。历史万人记录归入原版本档案。

## 源码与复核

E盘源码压缩包集中提供本次Web更新；原生历史工程继续保存在公开仓库和原归档。

- browser-worker/：v1.5.0完整Worker及D1迁移。应用依赖服务端事务与授权，部署须绑定自己的数据库及服务端配置。
- implementation/：node implementation/assemble.cjs重建当前候选，默认写入browser-worker。VENUE_LL_VARIANT=baseline可构建保留的对照实现；运行前保留当前构建。
- review-tools/low-latency/：Node24和Python3下执行node --test --test-concurrency=1 review-tools/low-latency/suite.cjs，VENUE_TEST_PYTHON可指定已有Python。所有账号和证明使用合成数据。
- cloud-load/driver/lowlat-producer.cjs：公开的分档压力脚本。工作流仅手动触发，执行需独立私有测试目标、有限测试窗口及专用临时凭据。
- validation/low-latency-v1.5.0/：完整统计、断言、阶段分解、原始采样哈希索引及构建绑定。最终压力、界面验收和交付Worker字节一致；完整原始记录单独保存在E盘。
- 公开仓库中的ArkTS工程和server/为保留的原生/本地历史组件；对应证据按原版本使用。

本机操作先做有界总CPU采样；70%停止启动新工作，Git/rg采用更严格的60%准入、单飞与线程限制。测试使用单任务和低优先级，不操作其他任务进程。
