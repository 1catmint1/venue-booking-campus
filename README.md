# 北理场馆预约：Web v1.4.0 共享库存 / 原生 v1.3.0

服务校园课余锻炼、周期社团训练和场馆日常协作。正常网页入口升级为跨访客共享预约库存，十二角色模拟工作台与个人资料按访客隔离。学校认证与资金支付均明确标注为模拟；不代表学校官方服务或应用市场上架。原复现基线和私有历史归档保留。

[正常共享体验入口](https://venue-booking-mobile-demo-20261014.woodsyguppy2048.chatgpt.site/)

## 版本与运行

- browser-worker/worker/index.js：Web v1.4.0 完整应用 Worker，包含原预约、推荐、证明、角色授权、差异计价与共享库存事务。依赖服务端 D1/兼容SQLite适配，不能作为纯静态网页发布。
- implementation/：从保留的v1.3基底重建Worker的增量源码；node implementation/assemble.cjs。部署需注册自己的服务端项目，配置自己持有的数据库绑定和服务端密钥；不提供个人平台身份和运行凭据。
- review-tools/shared-app/：Python3与Node24下执行 node --test --test-concurrency=1 review-tools/shared-app/suite.cjs，必要时用VENUE_TEST_PYTHON指定已有Python。测试只创建合成数据。
- 根目录ArkTS工程与server/server.cjs仍为原生/本地v1.3.0历史组件。原生完整构建、共享鸿蒙PC安装及首页验证已有证据，v1.4.0原生共享业务尚未构建和实测。
- Windows联网启动器打开上述共享入口，不会覆盖既有离线安装。

## 正常体验与隔离验收

预约、候补、模拟付款、财务退款和递补均使用实际应用RPC及同一共享事务实现。数据库独立限制容量，候补按持久受理序号排序；待支付和候补机会都有期限；金额使用本人认证状态重新报价、确认并保存快照，退款按原实付。旧各自独立的预约保留为只读演示历史，不能恢复为共享有效占用。

公网万人验证只在独立私有测试站与数据库开展。第一波为10000个预置合成会话的实际预约请求；候补阶段限速约640请求/秒，完整校验9999条序号及16次支付退款递补。不代表万人首次加载网页/登录、真实资金或任意规模的容量承诺。确切结果、失败尝试与CPU守卫见《共享库存应用验收记录》。
